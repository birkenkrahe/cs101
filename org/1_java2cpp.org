** Lessons

*** Concept transfers, ceremony changes

All three versions express the same idea:
- Bind names (=x=, =y=) to integer values.
- Output those values in a specific format.

The amount of scaffolding varies:
- Java requires a ~class~ and ~public static void main~.
- C++ requires ~main~, headers, and stream output (~cout~).
- Python runs top-level code directly.

*** Output formatting is a first-class skill

Requirements matter:
- The literal comma + space =", "= is required
- Printing two items is not the same as printing a list

Printing is conceptually *stream-based* but not always explicit:
- Python: ~print~ is built-in and hides the output stream (~sys.stdout~).
- C++: output written to a stream (~std::cout~) provided by ~<iostream>~.
- Java: output written to stream object (~System.out~), and ~println~ is a
  method on that stream.

Language-specific formatting shows up immediately:
- Java: string concatenation with ~+~
- C++: stream insertion (~<<~) and explicit newline (~endl~)
- Python: f-strings vs. concatenation

*** Types are explicit in C++/Java, implicit in Python

- Python hides type declarations but not types
- C++/Java forces you to announce the type up front

*** Imports/includes are dependencies

Only add dependencies when you use them:
- C++ requires ~#include <iostream>~ to use ~std::cout~
- Java: no ~import~ is required because ~System~ is in ~java.lang~
- Python: no import needed here.

*** Names don't come from nowhere

The prefix ~std::~ reminds you that names have owners:
- C++: ~std::~ is a name qualifier because ~cout~ lives in ~std~, which is
  also where the standard library lives (and you must say so)
- Python: built-ins live in an implicit global namespace
- Java: classes are grouped into packages, often hidden by imports
  (~System.out~ - ~System~ is a class in a built-in package)

** Follow-up questions:

1. What's ~public static void main~ in Java about?
   #+begin_quote
   - ~public~: all ~class~ members accessible from anywhere.
   - ~static~: method belongs to the ~class~ not to any object instance.
   - ~void~: function does not require a ~return~ value.
   - ~main~: name the Java runtime looks for as program entry point.
   #+end_quote

2. How does Python manage to be so much simpler?
   #+begin_quote
   Python trades control for convenience by fixing many decisions on
   the programmer's behalf: no ~main~, no ~class~ wrapper, no type
   declarations (~int~), no ~include~ or ~import~ for basic
   functions. Python removes choices, Java exposes some, C++ exposes
   even more: memory layout (stack vs. heap), value vs. reference etc.
   #+end_quote

3. Why doesn't everyone just program Python?
   #+begin_quote
   Simpler syntax does not mean simpler computation. Many problems
   cannot afford to trade control (of the program) for convenience (of
   the programmer): Python is slow, hides security details, it's great
   as glue or interface and almost always sits on top of C or C++, it
   scales poorly to very large codebases. Python = automatic shift,
   C++ = manual shift.
   #+end_quote

4. Where do names live in each language?
   #+begin_quote
   Python built-ins, Java packages, C++ namespaces.
   #+end_quote

5. What decisions does the language make for you, and which does it
   force you to make?
   #+begin_quote
   Variable types, memory, program entry, output, format.
   #+end_quote

** Follow-up questions

1. Why does ~printf~ require ~%d~ for integers?
   #+begin_quote
   Because ~printf~ uses a format string to interpret raw arguments: ~%d~
   tells it to interpret the corresponding vaue as ~int~ and print it.
   #+end_quote
2. What happens is =a= or =b= are changed after computing =sum=?
   #+begin_quote
   =sum= retains its value computed at the time of assignment unless it
   is explicitly reassigned. This could only be changed with *pointers*.
   #+end_quote
3. Why does Python no require declaring =sum= as integer?
   #+begin_quote
   Python uses dynamic typing: names are bound to objects at runtime,
   and the type is inferred from the assigned value.
   #+end_quote
4. Could the output be produced without storing the result in =sum=? Why
   might that be discouraged?
   #+begin_quote
   Yes, you could print =a+b= directly. Discouraged because it hides
   intermediate results and makes later reuse/modification harder.
   #+end_quote

** Lessons

- Floating-point variables represent *approximate* real numbers.
- All three languages use the same arithmetic expression: =result = x * y=.
- Java and C++ require explicit floating-point types (=double=).
- Python infers floating-point types from literal values.
- C++ ~printf~ uses ~%f~ format specifiers, which require attention to
  *precision* (e.g. ~%.1f~).
- The C++ ~<iomanip>~ header file allows you to set floating-point
  precision.

** Follow-up questions

1. Why do Java and C++ use =double= instead of =float= by default?
   #+begin_quote
   Because =double= provides higher precision and is the standard default
   floating-point type in most modern systems.
   #+end_quote
2. Why does ~printf~ require ~%f~ instead of ~%d~?
   #+begin_quote
   Because floating-point values have a different binary representation
   than integers and must be interpreted differently when printed.
   #+end_quote
3. Why might floating-point results look “unexpected”?
   #+begin_quote
   Because many decimal numbers cannot be represented exactly in binary,
   leading to rounding errors.
   #+end_quote
4. Why is initializing =result= to =0.0= still good practice?
   #+begin_quote
   It makes intent explicit and avoids accidental use of uninitialized
   variables.
   #+end_quote
5. Why do =std::fixed= and =std::setprecision= affect all subsequent
   output sent to =std::cout=?
   #+begin_quote
   Because =std::fixed= and =std::setprecision= modify the internal
   formatting state of the output stream. Once set, they remain in
   effect for all later output to that stream until changed again.
   #+end_quote

** Lessons

- Type conversion changes how a value is interpreted and may lose
  information.
- Converting from =double= to =int= truncates the fractional part.

  operation.

** Follow-up questions (with answers)

1. Why is the printed result =27= and not =28=?
   #+begin_quote
   Because converting from =double= to =int= truncates the fractional
   part. The value is about 27.07593, and truncation removes
   everything after the decimal point.
   #+end_quote

2. What information is lost during this type conversion?
   #+begin_quote
   The fractional part of the floating-point number is discarded when
   converting to an integer.
   #+end_quote

3. Why does C++ use =static_cast<int>= instead of =(int)= here?
   #+begin_quote
   Both forms are checked at compile time, but =(int)= is ambiguous: it
   may perform different kinds of conversions depending on
   context. =static_cast<int>= restricts the operation to a
   well-defined, compile-time numeric conversion and makes the
   programmer’s intent explicit.
   #+end_quote

4. What would change if the order of operations were reversed?
   #+begin_quote
   Converting to =int= before adding would discard precision earlier and
   produce a different result.
   #+end_quote

** Lessons

** Follow-up questions (with answers)

1. Why does array indexing start at 0?
   #+begin_quote
   Because arrays are based on contiguous memory, and the first
   element is located at an offset of zero from the start of the
   array.
   #+end_quote

2. What happens if you access an index outside the array bounds?
   #+begin_quote
   In C++, the behavior is undefined and may lead to incorrect results
   or crashes. In Java, the program throws a runtime exception.
   #+end_quote

3. Why is a loop a natural way to work with arrays?
   #+begin_quote
   Because arrays store sequences of values, and loops allow the same
   operation to be applied to each element systematically.
   #+end_quote

4. Can array elements be modified after they are stored?
   #+begin_quote
   Yes. Individual elements can be reassigned by indexing into the
   array and assigning a new value.
   #+end_quote

5. Is an array itself a single value or multiple values?
   #+begin_quote
   An array is a single object or variable that contains multiple
   values internally.
   #+end_quote
