* Hard pivot from C++ to Java

- We are not switching because C++ is “bad” or Java is “better”.

- We are switching because: We have already learned:
  + arrays
  + memory
  + pointers

- That gave us *mechanical understanding*

- Now we want to focus on:
  + abstraction
  + data structures
  + behavior

- Our upcoming structures are not defined by memory layout but by
  allowed operations:
  1) list - add/remove/get/set
  2) stack - push/pop
  3) queue - enqueue/dequeue
  4) map - get/put/remove

- Now, after C++, you know what is abstracted away. In C++, you
  controlled the data directly. In Java, you control the behavior of
  the data.

- We move from *focusing on how data lives in memory* to *focusing on
  what data does through its interface*.

  | C++ (so far)               | Java (now)                    |
  |----------------------------+-------------------------------|
  | Where is the data?         | What can I do with the data?  |
  | How is memory laid out?    | What operations are allowed?  |
  | Can I access this address? | What methods define behavior? |

* Procedural vs. object-oriented programming

- Most disciplines that grow over time are not just cobbled together:
  People identify patterns that are successful, explore and pursue
  them, and finally turn them into standards (until they fail).

- These patterns are also called "paradigms" (παραδείγματα). Two
  important programming paradigms are procedural and object-oriented
  programming.

- What does *procedural* mean? What does it achieve?
  #+begin_quote
  Procedural programming is centered on creating procedures or
  functions. Its main purpose is modularization.
  #+end_quote

- What is *object orientation*?
  #+begin_quote
  Object-orientation means that *everything is an object*. Each object
  has its own *state* and *behavior*.
  #+end_quote

- What does object orientation *achieve*?
  #+begin_quote
  Computation happens by message exchange between objects, like a
  conversation between agents. It enables *encapsulation* (of data),
  *inheritance* (of objects), and *polymorphism* (at compile-time or at
  run-time).
  #+end_quote

- How does that look like?
  #+begin_quote
  In OOP, computation happens by sending messages to objects:
  - =lamp.turnOn()= sends a message to a =lamp= object to turn on.
  - =account.deposit(100)= sends a message to an account object to
    deposit $100.
  #+end_quote

* Example: a light switch as message exchange between objects

- Open OneCompiler.com/java and code along with me.

- Example 1: A light switch

  #+name: LightDemo 44h5p8drx
  #+begin_src java :classname LightDemo :dir ../src :results output
    // Light represents a device that knows how to perform actions
    // It exposes behavior through public methods (its interface)
    class Light {
        public void turnOn() {
            System.out.println("Light is on.");
        }

        public void turnOff() {
            System.out.println("Light is off.");
        }
    }

    // Switch does not control the Light directly.
    // It does NOT change its internal state.
    // Instead, it sends messages to the Light
    class Switch {
        private Light light; // Reference to the Light object

        public Switch(Light l) {
            // The switch is connected to a specific Light
            // It knows where to send messages
            light = l;
        }

        public void flip(boolean on) {
            // The switch decides which message to send
            if (on) light.turnOn(); // send "turnOn" message to Light
            else light.turnOff(); // send "turnOff" message to Light
        }
    }
    public class LightDemo {
        public static void main(String[] args) {
            // Create a Light object (receiver of messages)
            Light lamp = new Light();
            // Create a Switch object and connect it to the Light
            Switch s = new Switch(lamp);

            // These calls don't manipulate Light directly
            // instead the send messages to the Switch
            s.flip(true); // Switch forwards "turnOn" to Light
            s.flip(false); // Switch forwards "turnOff" to Light
        }
    }
  #+end_src

  #+RESULTS: LightDemo 44h5p8drx
  : Light is on.
  : Light is off.

* For comparison: C++ version of the Light Demo

- Here is a working program in C++ that does the same thing,
  demonstrating how Java abstracts the memory manipulation away by
  replacing pointers

  #+begin_src C++ :results output :main no :includes
    #include <iostream>
    using namespace std;

    class Light {
    public:
      void turnOn() {cout << "Light is on.\n";}
      void turnOff() {cout << "Light is off.\n";}
    };

    class Switch {
      Light *light; // knows where to send the message
    public:
      Switch(Light *l) : light(l) {}; // flips the switch
      void flip(bool on) {
        if (on)
          light->turnOn(); // sends 'turnOn' message
        else
          light->turnOff(); // sends 'turnOff' message
      }
    };

    int main()
    {
      Light lamp; // create a lamp
      Switch s(&lamp); // create a switch for the lamp
      s.flip(true); // throw the switch
      s.flip(false); // throw the switch
      return 0;
    }
  #+end_src

- Differences C++ vs. Java
  | Aspect                   | C++                                            | Java                                                |
  |--------------------------+------------------------------------------------+-----------------------------------------------------|
  | References / pointers    | explicit pointers (=Light *=, =&lamp=, =->=)         | Implicit references (no =&=, no =->=, use =.=)            |
  | Memory model             | Stack objects + manual pointer use             | Objects via references; automatic memory management |
  | Method call syntax       | =light->turnOn()=                                | =light.turnOn()=                                      |
  | Constructor style        | Initializer list (=: light(l)=)                  | Assignment in body (=light = l;=)                     |
  | I/O                      | =cout << ...=                                    | =System.out.println(...)=                             |
  | Includes / imports       | =#include <iostream>=                            | No import needed for basic output                   |
  | Main function            | =int main()=                                     | =public static void main(String[] args)=              |
  | Object creation          | =Light lamp;=                                    | =Light lamp = new Light();=                           |
  | Passing object to Switch | =Switch s(&lamp);=                               | =Switch s = new Switch(lamp);=                        |
  | Access to members        | =public:= / =private:= sections                    | =public= / =private= per member                         |
  | Abstraction level        | Can operate at pointer or object level         | Object-level only (no pointer access)               |
  | Error model              | Possible pointer errors (dangling, null, etc.) | No pointer arithmetic; safer access model           |
  | Pedagogical emphasis     | Memory + message passing via addresses         | Encapsulation + behavior via methods                |

- Note:
  - In procedural style, all functions live in one scope.
  - In OOP style, related behavior is grouped in a class.
  - Java supports method overloading by parameter types.

- What happens if the first =add= method is declared ~private~ instead of
  ~public~? What happens if all =add= methods are declared ~private~?
  #+begin_quote
  - If =add(int, int)= is ~private~, it cannot be used from outside the
    class. Java then picks another accessible overloaded method (e.g.,
    =add(double, double))= using type conversion, so the program still
    runs but calls a different method.
  - If all =add= methods are =private=, none are accessible, so the
    program will not compile.
  - A ~private~ function cannot be called from another ~class~. It is
    ignored in overload resolution outside the class.
  #+end_quote

* Everyday example of encapsulation: the car

- What's part of the car's "user interface"? (What can you see/use?)
  #+begin_quote
  To use a car (as driver)

  + Ignition switch
  + Steering wheel
  + Gas pedal
  + Brake pedal
  + Gear shift
  + Dashboard display
  #+end_quote

  #+begin_quote
  The mechanisms hidden from the user to be able to use it.

  + Steering column
  + Fuel injection
  + Transmission system
  + Brake hydraulics

* Classes and objects

- What is a ~class~? A ~class~ is three things: *keyword*, *code*, and *concept*.

- As a *keyword*:
  #+begin_quote
  As a *keyword* a ~class~ is a specifier for a user-defined *type* that you
  can use to cast data in any (digital) form you like. You can make
  your own categories.

  So for example, the =Light= class allowed us to define a =lamp=. As an
  object, a =lamp= is like an integer or a string: memory + action.
  #+end_quote

- As *code*:
  #+begin_quote
  As code, a ~class~ specifies (aka encapsulates) the attributes
  (properties, data) and behavior (functions, methods) that an *object*
  of that class may have.

  Example: The =Counter= class had one attribute, the =count=, one
  accessor/getter method, =getCount()=, and three update/setter methods,
  =increment= (with/without parameter), and =reset()=.
  #+end_quote

- As a *concept:*
  #+begin_quote
  As a concept, a ~class~ it is the *description* of an object, like a
  blueprint:
  #+end_quote
  #+attr_html: :width 400px :float nil:
  #+caption: Blueprint of a house.
  [[../img/blueprint.png]]

- The blueprint can be used to build any number of objects, or
  *instances*.

        private double length;
        // public methods

        }

* Separate interface and implementation in Java

- In C++, you used:
  + =.h= for declaration
  + =.cpp= for implementation
  + preprocessor to knit everything together

- In Java, the usual classroom equivalent is:
  + class signature and method declarations at the top
  + method bodies below
  + one public class per file

- Later, the stronger Java form is:
  + =interface= = API only, specifies *what*
  + =class= = implementation, specifies *how*

- Might give the stronger (production) file format as a bonus
  assignment (requires research).

* Constructors

- A constructor initializes a new object.

- In Java:
  + constructor name = class name
  + no return type
  + called with =new=

- Notice that the =Rectangle= class did not have an explicit constructor
  method but only an implicit default constructor =Rectangle()=.

* Example: =Counter= constructors

- Final code in [[https://tinyurl.com/Counter-Demo-java][tinyurl.com/counter-demo-java]]
  #+begin_src java :classname CounterDemo :dir ../src
    // Counter.java defines a counter
    class Counter {
        private int count; // integer instance variable
        public Counter() {} // default constructor (count = 0)
        public Counter(int initial) {count = initial;} // alternate constructor
        public int getCount() {return count;} // accessor method
        public void increment() {count++;} // update method (add 1)
        public void increment(int delta) {count+=delta;} // update method
        public void reset() {count=0;} // update method
    }
    // CounterDemo.java tests the Counter class
    public class CounterDemo {
        public static void main(String[] args) {
        Counter c; // reference variable declaration (no counter)
        c = new Counter(); // construct new counter, assign ref to c
        c.increment(); // increase counter by 1
        c.increment(3); // increase counter by 3 (now it's 4)
        int temp = c.getCount(); // temp stores 4
        c.reset(); // counter is set back to 0

        System.out.println("Counter is " + temp);
        }
    }
  #+end_src

  #+RESULTS:
  : Counter is 4
