OneCompiler has two organisational levels: 1) code, 2) file, and we'll
change them both.

1. Delete the existing code to start with your own program.
2. Click on the pen in the middle of the page to change the name of

** Basic Structure of a C Program

Every C program has a basic structure:

- Header information (/preprocessor/)
- =main= program ending with =return 0;=
- Program body enclosed in ={ }=
- Comments (optional) followed by =//=

The minimal version (no output):
#+begin_src C++ :results none
  main() // main function
  {      // start main program
    }    // end main program
#+end_src

C is a 100% subset of C++. Here is the C-style version of
=helloworld.cpp= - indentation is optional but useful:
#+begin_src C++ :results output :exports both
  #include <iostream> // import input/output functions
  int main(void) { // main program begins
    puts("Hello, world!"); // print greeting string
    return 0; // confirm that program finished
  } // main program ends
#+end_src

#+RESULTS:
: Hello, world!

And finally, the full C++ version of =helloworld.cpp=: It now includes a
program header that all programs should have.
#+begin_src C++ :results output :exports both
  // print "Hello, world!" to stdout (standard output)
    
  #include <iostream> // import input/output functions

  int main(void) { // main program begins
    // print string to stdout and end with new line
    std::cout << "Hello, World!" << std::endl;

    return 0; // confirm that program finished
  } // main program ends
#+end_src

#+RESULTS:
: Hello, World!

Your task:
1. Type the program (with comments) into the editor.
2. At the end of each line, press =Enter=.
3. At the start of a new line, press =TAB= to indent
4. The file is automatically saved.
5. Click =RUN= (or =CTRL + ENTER)= and check the =Output= field.

* C++ Compilation on Google Cloud Shell
** Objective

The goal of this tutorial is about using Google Cloud Shell (a Linux
VM): I introduce simple Linux commands, and we write, compile, and run
a C++ file.

This is important so that you understand what's behind compilation
even though on OneCompiler.com, the details are hidden from you.

** Getting to the terminal

1) Log into https://ide.cloud.google.com - the Linux VM will take a
   little time (30 sec) to spin up the first time and every time you
   return to it after a longer break, but it will remain yours with
   all the files you upload there (I am not sure what the limit is).

2) Instead of working with the Cloud editor, find the tiny terminal
   sign *>_* at the top of the screen to open the terminal. You're in!

3) Don't worry about Gemini, Google's AI though you can use it both in
   the terminal (start a command with ~gemini~) or in a separate window
   for help. It's pretty slow and generally inferior to ChatGPT, I
   find.

** Getting around the terminal and repeating commands

1) Commands to try:
   #+begin_example sh
   whoami   # your user name
   pwd      # present working directory
   ls       # files in pwd [at the start, this shows nothing]
   #+end_example

2) Make a directory for the class and go there:
   #+begin_example sh
   mkdir cs101   # make a directory
   cd cs101      # go there
   pwd           # check that you arrived
   #+end_example

3) We also looked at the built-in history: You can go through the
   sequence of commands you typed with the up- and the down-arrow, and
   you can list the 1000 last commands with ~history~. To run a command
   from that list directly, for example number =503=, enter =!503= at the
   prompt.

** Writing and saving the source code file

1) Linux has a simple editor, ~nano~ that we will use to write our program:
   #+begin_example sh
   nano helloworld.cpp  # opens editor on the file `helloworld.cpp`
   #+end_example
   
2) In the editor, use =CTRL + s= to save, =CTRL + x= to exit. Write the
   code exactly as follows (contains a syntax mistake):
   #+begin_src C++ :results none
     #include <iostream>

     int main() {
       std::cout << "Hello, world!" << std::endl
         return 0;
     }
   #+end_src

3) After saving the file, check on the command-line that it exists
   using the file listing command ~ls~. You can get a lot more
   information using ~ls -lt~ (long, time-ordered file listing).

** Compiling source code and running object (machine) code   

1) The C/C++ compiler is called ~gcc~ / ~g++~ (two commands for the same
   program). Call ~g++~ directly on your C++ program to generate an
   executable file:
   #+begin_example sh
   g++ helloworld.cpp
   #+end_example

   Since the file contains a syntax mistake, compilation will abort
   with this message:
   #+begin_example
   Error: expected ‘;’ before ‘return’
   11 |   std::cout << "Hello, world!" << std::endl
      |                                            ^
      |                                            ;
   12 |     return 0;
      |     ~~~~~~                                  
   #+end_example

   It's pretty clear: you need to add the missing semi-colon! Go back
   into ~nano~, fix the mistake, save and return to the command-line,
   then run ~g++ helloworld.cpp~ again.

2) Now things are peachy: Check your files with ~ls~ again, and you
   should see a new file, =a.out=. If you use ~ls -l~, you can see that it
   is an executable. Let's run it.

3) Instead of running it, entering the program name only runs into a
   problem: enter =a.out= and you get the message:
   #+begin_example sh
   a.out: command not found
   #+end_example
   This is so because the computer cannot see what you see! To find
   any file, it needs to be in the computer's ~PATH~. Enter:
   #+begin_example sh
   echo $PATH
   #+end_example
   You should get a list of directories (program locations) like this:
   #+begin_example sh
   /home/[your name]/.local/bin:/home/[your name]/. .../usr/local/games:/snap/bin
   #+end_example

4) A shortcut to adding the program location to the ~PATH~ is to use the
   dot ~.~ to indicate that the file is in the current working directory
   (~pwd~). This command will work (if your source file is error-free):
   #+begin_example sh
   ./a.out
   #+end_example

5) You don't need to save anything here, just exit by closing the tab,
   or by entering ~exit~ at the prompt in the terminal.
